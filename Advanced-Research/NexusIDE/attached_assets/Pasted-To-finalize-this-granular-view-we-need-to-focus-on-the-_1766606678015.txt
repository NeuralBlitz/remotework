To finalize this granular view, we need to focus on the Inter-Process Communication (IPC) and the Custom UI Logic that allows these disparate file structures to behave as a unified tool.
1. The Accessory Bar (Keyboard Bridge)
Since mobile keyboards lack keys like Esc, Tab, and Ctrl, the IDE must inject a custom input layer. This isn't just a row of buttons; it is a dynamic input injector.
Logic Flow:
 * Input Interception: When the user taps a symbol (e.g., {), the IDE doesn't just append text. It checks the LSP context.
 * Auto-Closing: If you tap {, the engine automatically inserts } and moves the cursor to the middle.
 * Sticky Keys: For mobile terminals, the "Ctrl" and "Alt" buttons on this bar are "toggleable" (latched), allowing you to perform Ctrl+C with two separate taps.
2. Granular Data Flow: "The Lifecycle of a Keystroke"
To maintain 60 FPS performance while editing, the data flow must be asynchronous.
 * Main Thread (UI): Captures the raw onKeyPress.
 * Worker Thread (Buffer): Updates the "Shadow Document" (a string or Piece Table representing the file).
   * The Piece Table is an advanced data structure used by VS Code to handle large files by storing "original" and "added" text segments separately.
 * Analysis Thread (LSP): The Shadow Document is debounced and sent to the Language Server via JSON-RPC.
 * UI Re-render: The Editor View receives "Decorations" (e.g., red squiggles for errors) and overlays them on the text.
3. Advanced Feature: The Webview Previewer
For mobile web developers, "full functionality" means seeing changes in real-time.
 * Internal Proxy: The IDE runs a tiny local server (using Node.js or a native library).
 * In-App Browser: An <iframe> or WKWebView (iOS) points to localhost:3000.
 * Hot Module Replacement (HMR): The IDE's file system bridge detects a save, triggers the build tool in the background container, and sends a "reload" signal to the webview.
4. The "Multiplayer" Sync Logic
If you are building a collaborative IDE, the file structure includes a Sync Engine.
| Component | Responsibility |
|---|---|
| Operational Transforms (OT) | Resolves conflicts when two people type at the same time. |
| Presence Service | Shows the cursor position and name of other users in the gutter. |
| Delta Compression | Instead of sending the whole file over 5G, only the changed "diff" is transmitted. |
5. Deployment & Build Pipeline (CI/CD)
Because a mobile IDE often bundles compilers, the build process is unique:
 * Cross-Compilation: You must compile tools like Python, Node, or Git for arm64 (mobile) architecture.
 * Toolchain Bundling: These binaries are compressed and placed in the /assets folder of the app.
 * On-First-Run: The app extracts these tools into its "Internal Storage" and adds them to its internal $PATH so the terminal can find them.
